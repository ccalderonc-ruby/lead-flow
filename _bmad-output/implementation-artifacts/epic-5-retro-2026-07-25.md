## What went well

- Epic felt **fast, easy, and straightforward** by following professor comments and patterns from earlier code (seeds, Pundit, FormFields, leads index).
- Full admin vertical shipped: reliable demo logins (`DemoSeeds`), user CRUD with disable, read-only roles matrix, stage + assignee lead filters.
- Review → patch → defer held: trust-boundary findings (last admin, disabled sessions, filter ID hygiene, label honesty) were patched; course-scale residuals stayed labeled.
- Epic 4 process commitments largely completed before/during this epic (triage rule, a11y hook, 5.1 kickoff).

## Challenges

- **Stacked PRs** — 5.4 branched off unmerged 5.1–5.3; #30 briefly showed the full Epic 5 stack until `dev` was merged into the feature branch after #29 landed.
- **Dangerous edge cases** still needed adversarial review to surface (self-protection, live sessions after disable, forged/non-assignable filter IDs) even when the happy path was clear.

## Key insights

1. **Prior art accelerates admin polish** — professor notes + existing CRM patterns beat greenfield guessing.
2. **Merge before stacking** — one open PR per story keeps review diffs honest.
3. **Happy path ≠ trust boundary** — ship the feature, then patch self-harm / forged-param cases; don’t defer those.
4. **Epic 6 will not feel like Epic 5** — jobs, Stripe, webhooks, gating, and deploy need the same (or stricter) care as the 5.2/5.4 security patches.
